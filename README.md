# 📘 Документация Telegram-бота поддержки

## 1. Общее описание

Данный Telegram-бот представляет собой **бот-помощник службы поддержки**, который:
- Приветствует пользователя и предлагает задать вопрос;
- Показывает меню часто задаваемых вопросов (FAQ) с кнопками;
- Отвечает на типовые вопросы (оформление заказа, статус, отмена, повреждённый товар, доставка, поддержка);
- Перенаправляет нетиповые вопросы оператору;
- Обеспечивает двустороннюю переписку между пользователем и оператором через пересылку сообщений.

---

## 2. Требования и зависимости

### 2.1. Библиотеки
```python
import telebot
from telebot import types
```
- **pyTelegramBotAPI** (`telebot`) — основная библиотека для работы с Telegram Bot API.

### 2.2. Глобальные переменные (должны быть объявлены до запуска)
| Переменная | Тип | Назначение |
|---|---|---|
| `bot` | `telebot.TeleBot` | Экземпляр бота, инициализируется токеном |
| `OPERATOR_ID` | `int` | Telegram ID оператора поддержки |
| `waiting_for_operator` | `set` | Множество ID пользователей, ожидающих передачу вопроса оператору |

Пример инициализации:
```python
bot = telebot.TeleBot("YOUR_BOT_TOKEN")
OPERATOR_ID = 123456789
waiting_for_operator = set()
```

---

## 3. Структура и функциональность

### 3.1. Команда `/start`
**Обработчик:** `send_welcome(message)`

**Назначение:** приветствие нового пользователя.

**Действие:**
- Отправляет приветственное сообщение:
  > «Привет! Я твой Telegram бот-Помощник! Напиши мне свой вопрос, а я постараюсь тебе на него ответить.»

**Триггер:** команда `/start`.

---

### 3.2. Команда `/help`
**Обработчик:** `sendhelp(message)`

**Назначение:** вывод меню часто задаваемых вопросов (FAQ).

**Действие:**
1. Формирует `InlineKeyboardMarkup` с 7 кнопками:
   | Кнопка | callback_data |
   |---|---|
   | Как оформить заказ? | `answer_ofor` |
   | Как узнать статус моего заказа? | `answer_stat` |
   | Как связаться с вашей технической поддержкой? | `answer_help` |
   | Как узнать информацию о доставке? | `answer_info` |
   | Как отменить заказ? | `answer_otmen` |
   | Что делать, если товар пришел поврежденным? | `answer_brak` |
   | Другое | `answer_drugoe` |
2. Отправляет сообщение «Выберите вопрос» с клавиатурой.
3. Дополнительно отправляет подсказку «Пришлите свой вопрос!» (см. примечание в разделе 6).

**Триггер:** команда `/help`.

---

### 3.3. Обработка нажатий Inline-кнопок
**Обработчик:** `on_click(call)`
**Фильтр:** `func=lambda call: True` (все callback-запросы)

**Назначение:** ответы на типовые вопросы из меню `/help`.

**Логика по `callback_data`:**

| callback_data | Ответ бота |
|---|---|
| `answer_ofor` | Инструкция по оформлению заказа через корзину |
| `answer_stat` | Как посмотреть статус в разделе «Мои заказы» |
| `answer_otmen` | Рекомендация связаться со службой поддержки для отмены |
| `answer_brak` | Инструкция при повреждённом товаре (фото + обращение в поддержку) |
| `answer_help` | Способы связи с техподдержкой (телефон на сайте / чат-бот) |
| `answer_info` | Где найти информацию о доставке |
| `answer_drugoe` | Переход в режим ожидания оператора (см. п. 3.4) |

**Особый случай — `answer_drugoe`:**
1. Добавляет `call.from_user.id` в `waiting_for_operator`.
2. Отправляет сообщение: «Напишите ваш вопрос одним сообщением — я передам его оператору, и он ответит вам здесь.»
3. Вызывает `bot.answer_callback_query(call.id)` для снятия «часиков» с кнопки.

---

### 3.4. Передача сообщения пользователя оператору
**Обработчик:** `relay_to_operator(message)`
**Фильтр:** `m.from_user.id in waiting_for_operator`, типы контента: `text`, `photo`, `document`

**Назначение:** пересылка вопроса пользователя оператору.

**Алгоритм:**
1. Удаляет пользователя из `waiting_for_operator` (режим действует на **одно** сообщение).
2. Пересылает сообщение оператору через `bot.forward_message(OPERATOR_ID, ...)`.
3. Отправляет оператору подсказку:
   > «↩️ Ответьте реплаем на сообщение выше, чтобы написать пользователю {ФИО} (id: {id}).»
4. Уведомляет пользователя: «✅ Сообщение передано оператору. Ожидайте ответа.»

---

### 3.5. Ответ оператора пользователю
**Обработчик:** `relay_from_operator(message)`
**Фильтр:** `m.from_user.id == OPERATOR_ID`, типы контента: `text`, `photo`, `document`

**Назначение:** доставка ответа оператора пользователю.

**Алгоритм:**
1. Проверяет, что сообщение оператора является **реплаем** на пересланное сообщение пользователя (`message.reply_to_message.forward_from`). Если нет — отправляет оператору предупреждение:
   > «⚠️ Ответьте реплаем на сообщение пользователя, чтобы я знал, кому писать.»
2. Извлекает `user_id` из `message.reply_to_message.forward_from.id`.
3. Копирует сообщение оператора пользователю через `bot.copy_message(user_id, OPERATOR_ID, message.message_id)` — так оператор остаётся «анонимным».

---

### 3.6. Вспомогательная функция `getquestions`
**Назначение:** заготовка/заглушка для обработки вопроса (в текущем коде **не используется** — вызов закомментирован).

**Логика:** просто отвечает пользователю тем же текстом (`bot.reply_to(message, text)`).

## 5. Ограничения и особенности реализации

| Особенность | Описание |
|---|---|
| Режим ожидания оператора | Активируется **только** через кнопку «Другое». Действует на одно сообщение. |
| Типы контента | Поддерживаются только `text`, `photo`, `document`. Голосовые, видео, стикеры не обрабатываются. |
| Ответ оператора | Обязательно **реплаем** на пересланное сообщение, иначе бот предупредит оператора. |
| Анонимность | Ответ оператора копируется (`copy_message`), а не пересылается — личность оператора скрыта. |
| Состояние | Хранится в памяти (`set`). При перезапуске бота сбрасывается. |

## 6. Известные проблемы и рекомендации

1. **Лишнее сообщение в `sendhelp`**
   ```python
   answer = bot.reply_to(message, "Пришлите свой вопрос!")
   ```
   Строка отправляет пользователю сообщение «Пришлите свой вопрос!» сразу после меню, что может сбивать с толку. Рекомендуется удалить.

2. **Неиспользуемая функция `getquestions`**
   Вызов закомментирован, функцию можно удалить или доработать.

3. **Дублирование фильтров**
   Обработчик `relay_to_operator` и `relay_from_operator` имеют схожие фильтры по типу контента — при необходимости можно вынести в константу.

4. **Хранение состояния в памяти**
   При масштабировании (несколько процессов, перезапуск) рекомендуется использовать БД (Redis/SQLite) для `waiting_for_operator`.

5. **Отсутствие логирования**
   Рекомендуется добавить `logging` для отслеживания ошибок и действий пользователей.

6. **Обработка не-текстовых сообщений вне режима оператора**
   Сообщения, не попавшие ни под один обработчик, игнорируются. Можно добавить fallback-обработчик с подсказкой «Воспользуйтесь /help».

7. **Безопасность `OPERATOR_ID`**
   Токен и `OPERATOR_ID` следует хранить в переменных окружения (`.env`), а не в коде.
